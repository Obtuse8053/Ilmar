# ADR-0037: A model gateway in the egress sidecar, with worst-case cost reservations

- Status: Proposed
- Date: 2026-11-12
- Sources: [R14], [R21], [R29] · Findings: F-019
- Amends (by addition; no accepted text is edited):
  - **ADR-0029:** Mode 2's hard limits.
  - **ADR-0006:** narrows its single exception: the model key no longer
    enters the agent sandbox.
  - **ADR-0036:** closes the routes it leaves open.
- Supersedes for Mode 2: #111's TLS-terminating proxy and #94's LiteLLM
  gateway (deferred; ADR-0032 stays reserved).
- Asked for by the maintainer, 2026-11-12: conditional approval of the
  accelerated roadmap, amendments 1 and 2.

## Context and problem

Mode 2 runs unattended. It needs two things the current design does not give:

1. **The real model key outside the sandbox.**
   - Today the agent can read the key.
   - It can also use any other credential it finds against the allow-listed
     model host (ADR-0036's open routes).
2. **A finite, enforced dollar bound per attempt.**
   - A reservation (ADR-0029 §2) only decides whether an attempt may start.
   - The provider's workspace cap is monthly, and its overshoot is unproven.
   - A token counter alone does not bound dollars. Models, usage types and
     price tiers differ; requests run concurrently; and a response's usage is
     only known after it is paid for.

## Considered options

1. **LiteLLM (#94).** It brings Postgres and Redis failure modes, licence
   questions and an evaluation that may fail. Not needed for one repository
   with one execution at a time. **Deferred.**
2. **A TLS-terminating proxy (#111 as written).** It needs a CA that the
   sandbox trusts. That complexity is unnecessary if Claude Code accepts a
   plain-HTTP gateway URL on a private network.
3. **A gateway in the existing per-sandbox egress sidecar (chosen).** It
   reuses Ilmar's own proxy, network isolation and lifetime, and adds no
   external service.

## Decision

### 1. Topology and credential

- **The sandbox's route:** the sandbox reaches the model only through its
  own egress sidecar, at `ANTHROPIC_BASE_URL=http://<sidecar>:<port>`.
  - This is on the sandbox's private Podman network, which holds only the
    sandbox and its sidecar.
  - The sandbox's egress allow-list no longer includes the model host:
    **there is no direct network route from the agent to the provider.**
- **The throwaway token:** the sandbox gets a random, per-attempt token as
  `ANTHROPIC_API_KEY`.
  - The gateway accepts only that token.
  - It removes every credential header from the request and adds the real
    key.
- **The real key:**
  - It is passed to the sidecar container only, through the runtime's secret
    path, never through `ContainerSpec.env` (which never holds a secret) and
    never logged.
  - The sandbox cannot inspect the sidecar: it is a separate container with
    no shared process namespace, and it is coordinator-owned (ADR-0006).
- **HTTPS rule:** `ClaudeCodeSettings` keeps requiring HTTPS for an operator
  gateway. A plain-HTTP base URL is allowed only for the sidecar address that
  the runtime itself provides.
- **Prerequisite:** the pinned Claude Code must complete a run through a
  plain-HTTP gateway with only the throwaway token
  (`tests/integration/test_claude_code_gateway_compat.py`). Until that is
  recorded, no gateway code is merged.
- **Fallback if that check fails:** the smallest secure alternative is the
  same sidecar serving HTTPS.
  - It uses a per-sandbox self-signed certificate, generated by the
    coordinator.
  - The sandbox trusts it through `NODE_EXTRA_CA_CERTS`, which names a
    read-only file.
  - Nothing else in this decision changes.

### 2. Worst-case cost reservation per request

Every request reserves its worst-case cost before it is forwarded. The
gateway then settles it.

- **Attempt budget `B`:** the attempt's ledger reservation (ADR-0029 §2), in
  micro-dollars.
- **The admission rule:** the gateway forwards a request only if
  *settled + in-flight reservations + this request's worst case ≤ B*.
  Otherwise it answers with a refusal: no retry storm and no forwarding.
- **Allowed models:** only models in the operator's price table. The table
  gives, per model, the price per million tokens for:
  - input;
  - output (which includes thinking);
  - cache writes, at each duration used;
  - cache reads;
  - and any long-context tier.
  
  The operator attests that every price is at least the published price.
  Unknown models are refused.
- **Allowed usage types:** text and tool input and output, thinking, cache
  writes and reads, and image blocks.
  - Refused:
    - server tools, which are billed per use (web search, web fetch, code
      execution and the like);
    - document and PDF blocks;
    - MCP-connector fields;
    - batch;
    - files;
    - any field that selects a priced service tier or region.
  - Every request field is checked against an allow-list. An unknown field
    is refused.
- **Request limits:**
  - **Body size:** at most `max_request_bytes`.
  - **Output:** `max_tokens` is required and at most `max_output_tokens`;
    any thinking budget is within it.
  - **Concurrency:** at most `max_in_flight` requests at once.
  - **Initial values:** set from the compatibility test's record of what the
    pinned Claude Code sends.
- **The worst case of one request** = input bound × highest applicable input
  rate + `max_tokens` × output rate.
  - **Input bound:**
    - the request's body size in bytes, because a token is never shorter than
      one UTF-8 byte and JSON only adds bytes;
    - plus a fixed allowance per image block;
    - plus a fixed allowance for hidden tool-use system tokens.
  - **"Highest applicable rate":** the larger of the input, cache-write and
    long-context input rates. When the input bound exceeds a model's
    long-context threshold, the long-context output rate applies too.
  - **`count_tokens` requests** are free; they are forwarded without a
    reservation.
- **Settlement:**
  - **With complete usage:** the request is charged its actual usage at the
    correct tier, which is at most its reservation.
  - **Otherwise:** a response that is cut off, an unreadable usage block, a
    5xx response or a connection loss keeps the full worst case charged.
  - **No settlement exceeds the reservation,** and the rule above admits
    nothing past `B`.

### 3. The finite per-attempt bound

- **Per attempt:** with section 2, the dollar cost of an attempt is at most
  `B`. This rests on the provider charging no more than the operator's
  price table for the usage types allowed.
- **Per day and per month:** the ledger admits at most
  `floor(daily / B)` attempts per UTC day (and the monthly equivalent), so
  daily spend is at most `daily_usd` and monthly spend at most
  `monthly_usd`. These are proven upper bounds, not metered estimates.
- **The provider's workspace cap** stays an independent, separately tested
  backstop (Gate 1 cap drill).
- **What the bound depends on:**
  - **the operator's price table** being at least the real prices;
  - **the provider's metering** matching the documented usage types;
  - **the sidecar staying the only route.** That holds by the network
    design, and a real-Podman test checks it.

### 4. Failure behaviour (fail closed)

- **Sidecar gone:** the sidecar lives and dies with its sandbox (ADR-0029 §1
  lifetimes). If it dies, the agent loses its model route; it is never
  restarted mid-attempt, so no state is lost silently.
- **Upstream unreachable or refusing:** these are passed through as errors,
  so the runner's provider-error classification (ADR-0029 §5) still applies.
  A spend-limit or authentication refusal still suspends.
- **Malformed input:** a malformed request, an over-limit request, an
  unknown model or field, or a budget refusal is answered locally; nothing
  reaches the provider.
- **Accounting record:** the gateway records each request's reservation and
  settlement (amounts, model, sizes; never content) for the coordinator. A
  lost record never raises a charge above `B`.

## Consequences

- **Closes ADR-0036's open routes.**
  - The only credential in the sandbox is the throwaway token, so
    `~/.claude.json`, nested `claude` processes and a key copied into a
    candidate can use only it. It is worthless outside the attempt.
  - A credential found in the repository cannot reach the provider: there is
    no route, and the gateway accepts only its own token.
- **#110's secret scan still runs.** The configured secrets then no longer
  include the model key from the sandbox's point of view, but the scan stays
  as defence in depth.
- **Some agent requests are refused** (server tools, PDFs, unknown fields).
  The agent then fails or adapts, and the compatibility record shows whether
  the pinned Claude Code needs any of them.
- **The operator maintains a price table.** A wrong (too low) price breaks
  the bound, so the table is attested like the provider cap. A default table
  is never shipped as authoritative.

## Tests required

- **Compatibility (pinned, recorded):** the gateway-compatibility test,
  re-run through the real sidecar at the gate.
- **Unit tests for the worst-case bound:**
  - every model and tier;
  - the image allowance;
  - `max_tokens` missing or over its limit;
  - the body-size limit;
  - refusal of every unsupported usage type and unknown field;
  - in-flight limits under concurrency;
  - settlement that never exceeds the reservation;
  - every cut-off or unreadable response keeping the worst case;
  - property tests that no sequence of requests exceeds `B`.
- **Real Podman:**
  - the sandbox cannot reach the model host, or any host except its sidecar;
  - the real key appears nowhere in the sandbox: not in its environment, its
    files or `/proc`;
  - the gateway refuses requests without the throwaway token;
  - a stub upstream sees only the real key;
  - the budget refusal is observed end to end.
- **Workspace cap (Gate 1 drill):** still tested on its own.

## Revisit when

- More than one concurrent execution or repository is needed. LiteLLM or a
  shared gateway (ADR-0032) is then reconsidered.
- The provider adds usage types or price tiers that Claude Code uses.
- The pinned compatibility check fails. The HTTPS fallback above applies.
